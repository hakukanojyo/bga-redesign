# 開 PR 前的自我檢查

> 改寫自 ux-skills 的 `build-spec/REVIEW-AXES.md`。

開 PR 前，從三個角度看一遍自己的 diff。Prettier、ESLint、CI 已經會擋的不用再看。

## 1. 程式規範

照 `CLAUDE.md` 的規則，再加上這些常見問題：

- **Vue**：解構 props 或 `reactive` 後失去響應性；該用 `computed` 卻用 `watch`；`v-for` 沒有 `key`；在元件裡直接拿資料，沒有透過 `src/api/`；計時器或事件監聽沒有在 `onUnmounted` 清掉（例：開放桌每 10 秒刷新）
- **非同步**：Promise 失敗沒有處理；輸入很快變動時，舊的結果蓋掉新的；失敗後畫面卡在載入中；狀態用隨手寫的字串，沒有固定幾種（`idle`、`loading`、`success`、`error`）
- **安全**：用 `v-html` 顯示使用者輸入；`target="_blank"` 沒有 `rel="noopener"`；錯誤訊息露出程式內部的細節
- **設計系統**：寫死顏色或尺寸，沒有用 token；複製了一份共用元件，沒有直接用
- **套件**：加了套件卻沒有補 ADR
- **難懂的地方**：名稱看不出用途、同樣的程式寫了兩次、為了「以後可能用到」多寫的東西

## 2. 有沒有照規格

對照 issue、功能清單、PRD：

- 完成條件有沒有漏掉或只做一半
- 有沒有做了沒人要求的東西
- 看起來做完、其實做錯的地方

## 3. UX 和流程

打開畫面實際操作，不只看程式：

- **狀態**：issue 狀態表裡的每個狀態都做了、看得到；沒有卡住、沒有空白畫面
- **載入中**：出現時版面不跳；回應很快時骨架不會閃一下
- **失敗**：訊息說了發生什麼、下一步怎麼做；重試有效；使用者選的條件還在
- **空的**：看得出和失敗不一樣
- **換頁**：重新整理、直接開網址、上一頁和下一頁都正確；焦點和分頁標題有更新；沒有走不出去的頁面
- **無障礙**：只用鍵盤可以操作、焦點看得到、按鈕和欄位有名稱、狀態變化會被讀出來
- **文案**：同一件事用同一個名字，中文和英文、數字之間有空格
- **和設計稿比對**：在 1440 和 768 截圖，和 Figma 並排看。不一樣的地方標「刻意」或「要修」，「刻意」的寫進 PR 說明

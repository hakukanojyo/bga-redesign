# 稽核清單

> 改寫自 ux-skills 的 `ux-audit/CHECKLIST.md`。

release PR（`develop` → `main`）前、展示前跑一次。像第一次打開這個網站的人一樣，用慢的網路、只用鍵盤，試著把流程弄壞。

每一項給 🟢 沒問題、🟡 五分鐘內會被發現、🔴 展示會出事。

## 先看這裡：最容易漏掉的

1. Promise 失敗沒處理，留下空白畫面或永遠在轉的載入中
2. 部署後重新整理或直接開內頁變成 404
3. 換頁或關掉彈窗後焦點不見了，只用滑鼠的人不會發現
4. 失敗了卻沒有下一步，或重試後選好的條件不見
5. 載入中和失敗沒有被螢幕閱讀器讀出來
6. 空的被當成失敗，或失敗被當成空的
7. 骨架和內容尺寸不同，內容出現時按鈕被擠走、按錯
8. 很長的遊戲名稱、很大的數字撐破版面
9. 彈窗、側欄開著或篩選之後按上一頁，直接離開網站或沒反應
10. 連點兩次，加入了兩次
11. 只有在自己電腦上才走得通的流程（靠快取或本機資料）

## 1. 流程韌性

- 每一頁在載入中、空的、失敗、很慢（`?scenario=`）時都有東西可看；等超過 10 秒一定有訊息或出口
- 走完每個流程，瀏覽器的 console 沒有錯誤
- 失敗有人看得懂的訊息、重試有效、條件還在
- 空的、失敗、斷線看起來不一樣
- 連點、快速輸入、回應順序顛倒都處理好了
- 開放桌自動刷新時，正在看的那一列不會突然跳走

## 2. 網址和換頁

- 部署後的網址：每一頁都重新整理一次、在新的瀏覽器直接開一次
- 上一頁、下一頁正常；篩選、排序、分頁放在網址裡
- 404 頁看得懂、有路回首頁；沒有走不出去的頁面
- 換頁後焦點移到新的標題或主要區塊、捲回頂端、分頁標題有變

## 3. 無障礙（自動工具大約只抓得到三分之一）

- 只用鍵盤走完主流程：Tab 順序和畫面順序一樣、焦點一直看得到；彈窗鎖住焦點、Esc 關閉、關掉後焦點回到原本的按鈕
- 每個按鈕和欄位都有名稱；placeholder 不能當 label
- 非同步的變化會被讀出來：載入中、成功用 `role="status"`，失敗用 `role="alert"`
- 對比：文字 4.5:1，按鈕外框和焦點 3:1，停用、懸停、錯誤狀態也要
- 放大到 200% 不會出現橫向捲軸、文字不會被切掉
- 減少動態效果有效；不只靠顏色表達狀態；`<html lang="zh-Hant">`；標題層級照順序；圖片有意義的 `alt`

## 4. 版面和內容

- 1440、1280、1024、768、375 各截一次圖（375 要看到縮放的平板版和頂部橫幅）
- 最長的內容：很長的中文遊戲名、沒有空格的長英文字、兩位數的徽章、很長的列表、零筆結果。文字照設計換行或截斷，不會溢出
- 觸控裝置：懸停才出現的東西改成常駐；觸控尺寸夠大

## 5. 效能

- Lighthouse 跑部署後的網址
- 骨架尺寸和內容一樣；圖片有寬高、格式和大小合理；各頁分開載入
- 中文字型：完整的字型檔有好幾 MB，要切子集或用系統字型；確認字型還沒到時的樣子
- 背景模糊在低效能時有降級

## 6. 安全

- `npm audit` 看 `dependencies`，沒有 high 或 critical
- 網站裡沒有金鑰（`VITE_` 開頭的都是公開的）、git 紀錄裡也沒有、`.env` 有被 `.gitignore` 排除
- 沒有用 `v-html` 顯示使用者輸入；外部連結有 `noopener`
- 錯誤訊息和 console 沒有露出內部細節

## 7. 文案和一致性

- 按鈕是動詞；錯誤說明下一步；空狀態邀請使用者做點什麼；同一件事在每個地方同一個名字
- 日期、數字照台灣的格式；中文和英文、數字之間有空格
- 用 token、不寫死數值；用共用的狀態元件、不複製；重要畫面和 Figma 並排比對過

## 8. 展示準備

- 部署後的網址在乾淨的瀏覽器能用；主流程從頭走到尾，console 乾淨
- `?scenario=` 切換得到，假資料會重設
- 有備案：主流程和失敗畫面的螢幕錄影
- README 說明專案是什麼、線上網址、怎麼跑；`main` 的 CI 是綠勾；`docs/` 和現況一致

# 0005. 假資料放在 `src/api/` 後面，之後換 Supabase

- 狀態：已採用
- 日期：2026-11-03

## 背景

第一階段沒有後端，但畫面要有真實的感覺：載入中、失敗、空的狀態都要看得到。第二階段要換成 Supabase。

## 決定

- 畫面一律透過 `src/api/` 拿資料，不直接 import 假資料
- `src/api/` 的函式回傳 Promise，加一點延遲，和真的 API 一樣要等
- 網址加參數可以切換假資料的情境，例如 `?scenario=slow`、`error`、`empty`，展示時能直接看到載入中和失敗的畫面
- 遊戲資料從 BGA 取 20–30 款，遵守 robots.txt 和使用條款，頁尾標註版權
- 資料的欄位等 PRD 完成後一起定，再寫假資料

## 考慮過的選項

- **畫面直接 import JSON**：最快，但換 Supabase 時每個畫面都要改，也做不出載入中和失敗
- **一開始就接 Supabase**：比較真實，但資料模型還沒定，太早接會一直改資料表

## 代價

`src/api/` 多一層。換 Supabase 時只要改這一層，畫面不用動。

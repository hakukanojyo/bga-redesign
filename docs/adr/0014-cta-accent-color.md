# 0014. 首頁「立即遊玩」的顏色從橫幅自動取

- 狀態：已採用
- 日期：2026-11-05

## 背景

首頁主視覺會換遊戲（之後可能變輪播）。Figma 的「立即遊玩」是紅色，配合當時那張圖；換成別款遊戲，紅色可能跟橫幅打架。每款都請設計師挑顏色太花時間，遊戲一多也容易漏。

## 決定

- `npm run images` 壓縮橫幅時順便算**主色**（dominant color extraction），寫進 `src/assets/images/games/colors.json`
  - 只看鮮豔的像素（飽和度 ≥ 0.35、亮度 0.2～0.8），依色相分 24 組，取最多的那組平均
  - 再調深，直到白字的對比 ≥ 4.5:1（WCAG AA）
  - 整張都不鮮豔、或沒有橫幅：用品牌藍 `#0b72b5`
- `src/api/games.js` 把它放進遊戲的 `accentColor`；按鈕用 `--cta-accent` 接住，漸層、hover、按下的深淺在 `tokens.css` 用 `color-mix()` 算（`cta-accent`、`cta-accent-hover`、`cta-accent-pressed`）
- **這是「顏色只用 Semantic token」的例外**：顏色來自圖片，不是 Figma 變數。只用在依遊戲變色的 CTA，其他地方照舊只用 token

## 考慮過的選項

- **固定用 Figma 的紅色**：最簡單，但換遊戲就可能不搭
- **每款遊戲手動填顏色**：最準，但每加一款都要設計師挑，資料也多一欄要維護
- **在瀏覽器裡即時算（canvas 讀像素）**：不用多一個檔案，但每次開首頁都要算，圖片還沒載完按鈕也不知道是什麼顏色

## 代價

- 自動挑的顏色不一定是設計師會選的；不滿意的話，之後可以讓資料覆寫
- 換了橫幅要重跑 `npm run images`，`colors.json` 才會更新
